# 健身俱乐部综合管理系统

基于 Spring Boot + Vue3 的前后端分离健身俱乐部管理系统，支持管理员、教练、会员三类角色的全流程信息化管理。

## How to Run

### 方式一：Docker Compose（推荐）

```bash
# 启动所有服务
docker-compose up --build -d

# 查看日志
docker-compose logs -f

# 停止服务
docker-compose down
```

### 方式二：本地开发

#### 1. 数据库初始化

```bash
# 创建数据库并导入初始数据
mysql -u root -p < sql/schema.sql
```

#### 2. 启动后端

```bash
cd backend
mvn spring-boot:run
```

#### 3. 启动前端

```bash
cd frontend
npm install
npm run dev
```

## 题目内容

### 需求背景我需要完成毕业设计：基于Spring Boot的健身俱乐部综合管理系统设计与实现。系统采用前后端分离架构，核心目标是解决传统健身俱乐部管理效率低、数据不互通问题，支持管理员、教练、会员三类角色的全流程信息化管理。### 技术栈要求1. 后端：Spring Boot（版本建议2.7.x） + MyBatis-Plus（操作MySQL 8.0） + Spring Security（权限控制） + JWT（token认证）2. 前端：Vue3（+ Element Plus） + Axios（接口请求） + Vue Router（路由） + Pinia（状态管理）3. 数据库：MySQL，要求设计合理的表结构（含主键、外键、索引）### 核心功能模块（按角色拆分）#### 1. 系统管理员- 系统管理：用户角色权限管理（增删改查）、系统日志查看、数据备份/恢复- 会员管理：会员信息CRUD、会员等级/套餐管理、会员状态（冻结/激活）管理- 教练管理：教练信息CRUD、教练资质审核、教练排班管理- 课程管理：课程类型/课时CRUD、课程排期、课程审核（教练提交的调课/请假）- 器材和场地管理：器材信息（名称/状态/维护记录）CRUD、场地预约/使用记录管理- 财务管理：会员消费记录、教练薪资结算、收支统计#### 2. 教练- 个人课程管理：查看分配的课程、提交调课/请假申请、课程签到- 会员跟进：查看负责的会员列表、记录会员健身情况、发送健身建议- 业绩查询：按周/月查看课程销量、业绩提成统计- 基础操作：个人信息修改、密码重置#### 3. 会员- 个人中心：查看/修改个人信息、会员套餐到期提醒- 课程预约：查看可预约课程、预约/取消预约、查看预约记录- 消费记录：查看充值/购课/消费明细、导出记录- 健身数据：手动录入/查看健身记录（体重/训练时长等）、生成健身周报- 意见反馈：提交反馈、查看反馈回复状态### 代码生成要求1. 后端：- 按模块分层开发（controller/service/mapper/entity），符合RESTful接口规范- 实现JWT鉴权，不同角色接口权限控制- 核心表结构设计（至少包含：用户表、会员表、教练表、课程表、预约表、器材表、消费表）- 提供核心接口的测试用例（Postman/json格式）- 包含全局异常处理、日志打印、参数校验2. 前端：- 实现登录页、各角色的首页、功能模块页面（至少完成核心功能的UI）- 封装Axios请求拦截器（处理token）、响应拦截器（处理异常）- 实现路由守卫（不同角色访问不同路由）3. 交付物：- 完整的项目代码（后端+前端），包含pom.xml（后端）、package.json（前端）依赖文件- 数据库建表SQL语句- 核心接口文档（说明接口地址、请求方式、参数、返回值）- 简单的运行说明（如何启动后端、前端，如何配置数据库）### 补充说明- 优先实现核心功能（会员/课程/教练管理），次要功能（如数据备份、薪资结算）可简化- 代码需有注释，符合规范，便于毕业设计答辩讲解- 避免过度复杂的技术，保证系统能正常运行和演示

### 教练排班管理

教练排班功能通过以下方式实现：

1. **课程分配**：管理员创建课程时指定教练，自动形成教练排班
2. **排班查看**：通过 `GET /api/v1/coaches/{id}/schedule` 查看教练的课程安排
3. **请假管理**：教练可提交请假申请，管理员审核后自动处理相关课程
4. **冲突检测**：新建课程时自动检测教练时间冲突

### 会员套餐到期提醒

系统在以下场景提供到期提醒：

1. **个人中心弹窗**：会员点击右上角"个人信息"时，弹窗采用 Tab 布局：
   - **基本信息 Tab**：编辑姓名、性别、手机号
   - **会员套餐 Tab**：显示会员等级、账户余额、到期日期（已过期显示红色、7天内到期显示橙色）、已完成课程数、到期提醒横幅
   - **修改密码 Tab**：修改账户密码
2. **首页提醒**：会员登录时，若套餐即将到期（7天内），首页Dashboard会显示提醒横幅
3. **统计接口**：`GET /api/v1/statistics/member/dashboard` 返回 `daysUntilExpire`、`isExpired` 和 `isExpiringSoon` 字段
4. **会员列表**：管理员在会员管理页面可看到各会员的到期日期和状态

### Postman 测试集合

项目提供完整的 Postman 测试集合，包含所有核心接口的测试用例。

**导入方法：**

1. 打开 Postman
2. 点击 **Import** 按钮
3. 选择文件 `docs/postman_collection.json` 导入

**使用步骤：**

1. **获取Token**：展开"认证管理"文件夹，执行"管理员登录"请求
   - Token会自动保存到集合变量 `adminToken`
2. **测试接口**：登录成功后，即可测试其他接口
3. **切换角色**：执行"教练登录"或"会员登录"获取对应角色的Token

**集合特性：**

- 自动化Token管理（登录后自动保存到变量）
- 按模块分组（认证、会员、教练、课程等共14个分组）
- 内置测试脚本验证响应格式
- 支持管理员/教练/会员三种角色测试

**测试建议：**

```
1. 先执行"管理员登录"获取adminToken
2. 测试管理员相关接口（会员管理、教练管理等）
3. 执行"教练登录"获取coachToken
4. 测试教练相关接口（我的课程、业绩等）
```

## 安全特性

- **JWT认证**：使用 JSON Web Token 进行身份验证
- **密码加密**：使用 BCrypt 算法加密存储
- **请求限流**：通用API每分钟100次，登录接口每分钟10次
- **权限控制**：基于角色的访问控制 (RBAC)
- **空值检查**：后端接口对会员/教练信息进行空值校验，防止数据不一致导致的 500 错误

## 前端错误处理

系统实现了统一的前端错误处理机制，当用户操作遇到问题时会显示友好的中文提示：

| HTTP状态码 | 处理方式 |
| ---------- | -------- |

## 常见问题

### Docker启动后无法访问？

MySQL启动较慢，请等待约60秒让所有服务健康检查通过：

```bash
docker-compose ps  # 查看服务状态
```

### 如何查看服务日志？

```bash
docker-compose logs -f backend  # 查看后端日志
docker-compose logs -f frontend # 查看前端日志
```

### 如何重置数据库？

```bash
docker-compose down -v  # 删除数据卷
docker-compose up -d    # 重新启动
```

### 本地开发如何配置数据库？

修改 `backend/src/main/resources/application.yml` 或通过环境变量设置：

```bash
export DB_URL=jdbc:mysql://localhost:3306/fitness_club
export DB_USERNAME=root
export DB_PASSWORD=your_password
```

### 数据备份与恢复

系统提供完整的数据备份和恢复功能：

**备份功能：**
- 将会员、教练、课程、器材、反馈、消费记录等数据导出为JSON文件
- 备份文件包含时间戳和版本信息

**恢复功能：**
- **验证模式**：上传备份文件后，先验证文件格式和完整性
- **增量导入**：仅导入ID不存在的新记录，跳过已有数据（安全模式）
- **覆盖导入**：更新已存在的记录，同时导入新记录（需确认操作）

**恢复结果反馈：**
- 显示各数据表的导入数量和跳过数量
- 如有错误会详细列出错误信息
